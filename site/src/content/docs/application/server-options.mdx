## Description

Configure the listener, timeouts, request and response limits, execution mode, HTTP/2 and response compression with
`Options`. Use `MultipartOptions` for the separate limits on multipart fields and files.

1. Create the settings with `new Options()`, the only public constructor.
2. Call setters for the properties you want to change. Each new instance starts with the defaults below.
3. Pass the settings to `new Shoostr(options)`, then register routes.

A setter validates its input before assignment. If validation fails, the previous value stays in place. Passing
`null` resets that property to its default.

Shoostr takes a private copy during construction. Later edits affect only applications you construct afterward.
Finish updating the options before another thread uses them to construct an application.

| Setting                 | Default                                           | Setter                     |
|-------------------------|---------------------------------------------------|----------------------------|
| `host`                  | `0.0.0.0` (all IPv4 interfaces)                   | `setHost`                  |
| `port`                  | `8080`                                            | `setPort`                  |
| `maxRequestBytes`       | 1,048,576 buffered request bytes                  | `setMaxRequestBytes`       |
| `maxResponseBytes`      | 1,048,576 staged finite-response bytes            | `setMaxResponseBytes`      |
| `maxRequestHeaderBytes` | 8,192 bytes                                       | `setMaxRequestHeaderBytes` |
| `idleTimeout`           | 30 seconds                                        | `setIdleTimeout`           |
| `shutdownTimeout`       | 5 seconds                                         | `setShutdownTimeout`       |
| `http2`                 | `false`                                           | `setHttp2`                 |
| `compression`           | `false`                                           | `setCompression`           |
| `maxParameters`         | 1,000 decoded pairs per query or URL-encoded form | `setMaxParameters`         |
| `multipart`             | `new MultipartOptions()`                          | `setMultipart`             |
| `streamBufferBytes`     | 8,192 bytes per streaming response buffer         | `setStreamBufferBytes`     |
| `virtualThreads`        | `false`                                           | `setVirtualThreads`        |

Set values within these limits.

- **Host and port**. Use a nonblank host. The listener resolves host names at startup. Ports range from `0` to
  `65535`. Use `0` to let the operating system pick an available port, then read it with `app.port()` after startup.
- **Timeouts**. Use positive whole milliseconds that fit in a Java `long`. `idleTimeout` measures connection inactivity.
  `shutdownTimeout` controls Jetty's server drain. Request deadlines belong to the application, and total shutdown time
  also includes resource cleanup. Jetty applies a separate timeout when stopping its platform worker pool.
- **Byte limits**. Use positive values. `maxRequestBytes` must also be below `Integer.MAX_VALUE`.
- **Parameter count**. Set `maxParameters` to a positive value. Each query or URL-encoded form has its own limit.
  Repeated names count as separate pairs. See [request parameters](../../request/parameters/).
- **Multipart limits**. Set the aggregate, part and storage limits through [`MultipartOptions`](../../bodies/multipart/).

Use the boolean settings to select execution and transport behavior.

- **Execution**. Platform threads are the default. Call `options.setVirtualThreads(true)` to use virtual threads for
  ordinary handlers and managed WebSocket callbacks. Explicit endpoint executors and native pool configuration take
  precedence. See [executor selection](../../lifecycle/executors/).
- **HTTP/2**. Call `options.setHttp2(true)` to enable HTTP/2 with HTTP/1.1 fallback. The listener uses ALPN with TLS
  and h2c on plaintext connections.
- **Compression**. Call `options.setCompression(true)` to enable gzip for eligible responses. Use
  `response.disableCompression()` to opt out for one response. Incoming request bodies receive no automatic decompression.

You can load `Options` from external configuration and customize Jetty before startup.

- [Jetty callbacks](../native-configuration/) can override the initial transport settings. Shoostr still applies
  its buffered request-body and staged response limits.
- Choose your own external configuration parser. If it constructs `Options` and calls setters only for supplied
  properties, omitted settings keep their defaults. Duration conversion and nested multipart settings depend on
  the parser and how you configure it.

## Example

`ServerOptionsExample.application(String host, int port)` configures the listener and registers `POST /echo` to echo
a text body. It returns an unstarted application. The caller can finish configuring it before startup and owns its closure.

- `setMaxRequestHeaderBytes(1024)` sets the request header limit. The HTTP parser rejects oversized headers with
  `431` before the endpoint handler runs.
- `setMaxRequestBytes(1024)` sets the buffered request body limit. An oversized body receives `413`.
- The factory also sets a 2,048-byte staged response limit and a 4,096-byte streaming buffer. Multipart settings use
  their defaults.

## Test

All tests start an application from `ServerOptionsExample.application("127.0.0.1", 0)` and make HTTP requests to it.

- The direct-start test calls `app.start()`, reads the assigned port and sends an echo request. It also verifies that
  the configured HTTP parser returns `431` for oversized headers.
- The other tests use `TestServer`, which overrides listener binding with an available loopback port and owns
