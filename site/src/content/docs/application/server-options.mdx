## Description

`Options` holds application settings: listener binding, transport timeouts, parser and buffered-body limits, execution mode, HTTP/2, and response compression. Create it with `new Options()`, then configure its bean properties through setters. Pass it to `new Shoostr(options)` before registering routes. `MultipartOptions` supplies the related limits for multipart fields and files.

This application accepts a bind host and port and serves a POST `/echo` endpoint. The test selects loopback and an available port. Accepted input becomes the response. The tests exercise parser and buffered-body limits separately.

Every new instance initializes its field defaults. Set only the properties your application needs; each setter validates before assignment and retains the previous value if validation fails. Passing null resets only the selected property to its default. The no-argument constructor is the only public constructor. `Shoostr` captures a private snapshot during construction, so later changes to the supplied options affect only subsequent applications. Do not mutate options concurrently with application construction.

| Setting | Default | Setter |
| ------- | ------- | ----------- |
| `host` | `0.0.0.0` (all IPv4 interfaces) | `setHost` |
| `port` | `8080` | `setPort` |
| `maxRequestBytes` | 1,048,576 buffered request bytes | `setMaxRequestBytes` |
| `maxResponseBytes` | 1,048,576 staged finite-response bytes | `setMaxResponseBytes` |
| `maxRequestHeaderBytes` | 8,192 bytes | `setMaxRequestHeaderBytes` |
| `idleTimeout` | 30 seconds | `setIdleTimeout` |
| `shutdownTimeout` | 5 seconds | `setShutdownTimeout` |
| `http2` | `false` | `setHttp2` |
| `compression` | `false` | `setCompression` |
| `maxParameters` | 1,000 decoded pairs per query or URL-encoded form | `setMaxParameters` |
| `multipart` | `new MultipartOptions()` | `setMultipart` |
| `streamBufferBytes` | 8,192 bytes per streaming response buffer | `setStreamBufferBytes` |
| `virtualThreads` | `false` | `setVirtualThreads` |

The host must be nonblank. Host names are resolved when the listener starts. Ports range from `0` to `65535`; port `0` lets the operating system select an available port. Read the bound port with `app.port()` after startup.

Timeouts must be positive whole milliseconds representable by a Java `long`. `idleTimeout` measures connection inactivity. `shutdownTimeout` configures Jetty's server drain timeout; it is neither an application request deadline nor a total shutdown deadline. Jetty's platform-worker shutdown has its own timeout.

Byte limits must be positive, and `maxRequestBytes` must also be below `Integer.MAX_VALUE`. `maxParameters` must be positive and counts repeated pairs separately for each [query or form](../../request/parameters/). Multipart requests have separate aggregate, part, and storage limits in [`MultipartOptions`](../../bodies/multipart/), which this example leaves at their defaults.

Platform threads are the default. `options.setVirtualThreads(true)` selects virtual execution for ordinary handlers and managed WebSocket callbacks; explicit endpoint executors and native pool configuration take precedence. See [executor selection](../../lifecycle/executors/) for execution and resource ownership.

`options.setHttp2(true)` enables HTTP/2 with HTTP/1.1 fallback. It uses ALPN when TLS is configured and h2c without TLS. `options.setCompression(true)` enables gzip for eligible responses. Request-body decompression remains disabled. A response can opt out with `response.disableCompression()`.

These fields replace `app.virtualThreads()`, `app.http2()`, and `app.compression()`: set the corresponding boolean property on `Options` before constructing the application.

### Set the request header limit

Call `options.setMaxRequestHeaderBytes(1024)` before constructing `new Shoostr(options)`. The HTTP parser rejects oversized headers with `431` before the endpoint handler runs. Configure buffered request bodies separately with `setMaxRequestBytes`; exceeding that limit produces `413`.

Advanced [Jetty callbacks](../native-configuration/) can override the initial transport settings. They do not replace Shoostr's buffered-body and staged-response limits. Your application chooses any external configuration parser. For mappings that construct the bean and call setters for supplied properties, omitted properties retain their field defaults. Conversion of durations or nested multipart settings depends on the chosen parser and its configuration.
