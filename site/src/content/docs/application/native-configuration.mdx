## Description

Configure Jetty's own server objects before Shoostr starts the listener. For routine settings such as listener binding,
timeouts, request and response limits, execution, HTTP/2 and compression, use [`Options`](../server-options/).
This example sets native listener, HTTP parser and thread-pool values for an ordinary Shoostr route.

Register the callback for the object you need to configure. Shoostr passes that object to the callback during
startup. Use Jetty's API for the supplied object.

| Setting                                           | Native hook and reference                                                                                                                                                                                                                                                                                           |
|---------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Bind address, port, and connection idle timeout   | Default `ServerConnector` in `modifyServer`. See [connectors](https://jetty.org/docs/jetty/12.1/programming-guide/server/http.html#connector) and the [connector reference](https://javadoc.jetty.org/jetty-12.1/org/eclipse/jetty/server/ServerConnector.html).                |
| Request headers, HTTP parsing, and native buffers | `HttpConfiguration` in `modifyHttpConfiguration`. See [Jetty's HTTP settings](https://javadoc.jetty.org/jetty-12.1/org/eclipse/jetty/server/HttpConfiguration.html).                                                                                                     |
| Native platform pool settings                     | Existing `QueuedThreadPool` in `modifyServer`. See the [threading guide](https://jetty.org/docs/jetty/12.1/programming-guide/arch/threads.html).                                                                                                                         |
| Native shutdown timeouts                          | `Server` and existing `QueuedThreadPool` in `modifyServer`. See the [server](https://javadoc.jetty.org/jetty-12.1/org/eclipse/jetty/server/Server.html) and [pool references](https://javadoc.jetty.org/jetty-12.1/org/eclipse/jetty/util/thread/QueuedThreadPool.html). |

Choose [platform execution or virtual-thread opt-in](../../lifecycle/executors/) for your application.
Native pool configuration takes precedence.

Register callbacks before calling `app.start()`. Shoostr holds them until startup, then runs them in this order.

1. Apply the `modifyHttpConfiguration(...)` callbacks in registration order.
2. Install the default connector and application handler.
3. Apply the `modifyServer(...)` callbacks in registration order.

Native settings can override initial transport values from `Options`. Shoostr's buffered request and staged
response limits still apply. Shoostr rejects further registration after startup begins or the application closes.

## Example

`NativeConfigurationExample.application(int port)` binds to loopback and serves `ready` at `GET /health`.
Pass `0` to let the operating system select a port. Read it with `app.port()` after startup. In this example the
server callback finds the default connector at `server.getConnectors()[0]`.

Shoostr normally binds to `0.0.0.0:8080` with a 30-second connection idle timeout. The example sets these values to
demonstrate the native APIs.

- The HTTP callback sets a 1,024-byte request header limit.
- The server callback caps the platform pool at 32 threads and sets a 10-second connection idle timeout.
- The server callback sets a one-second server stop timeout.

The connection idle timeout measures inactivity. The server stop timeout controls Jetty's drain, and the platform
pool has its own shutdown timeout. Manage request deadlines separately. Choose pool settings for your workload.
See [Jetty's threading guide](https://jetty.org/docs/jetty/12.1/programming-guide/arch/threads.html).

Shoostr owns native startup and shutdown. Keep that ownership when you configure the server.

- Preserve Shoostr's application handler and default connector. You can wrap the handler and add connectors.
  `app.port()` continues to report the default connector's port.
- Leave Jetty unstarted in the callback and keep its separate JVM shutdown hook disabled. Leave server stop to Shoostr.
- Keep ownership of an executor you supply through a native setter unless you register its lifecycle with Jetty.
  Shoostr still cancels its own managed WebSocket work on that executor at shutdown.
  See [managed WebSockets](../../websockets/managed/).
- Close the application returned by the factory even if you never start it.

## Test

The test calls `NativeConfigurationExample.application(0)`, starts the application directly, and uses Java's
`HttpClient` on the assigned port. This exercises the configured listener. `TestServer` would override its binding.

- The test verifies callback timing and order, the listener and pool settings, and the server stop timeout.
- It checks a successful HTTP/1.1 response from `/health` and a `431` response for oversized headers.
- It checks that both callbacks reject further registration after startup and after closure.
