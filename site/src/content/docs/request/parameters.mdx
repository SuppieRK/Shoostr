## Description

Shoostr keeps path captures, query values, and URL-encoded form fields separate, even when they share a name.

This example reads each source from the handler's `Request`. Choose an accessor based on where the value comes from
and how many values you need.

| Source | First value by name | All values for one name, in arrival order | All entries       |
|--------|---------------------|-------------------------------------------|-------------------|
| Path   | `pathParam(...)`    | One capture per name                      | `pathParamMap()`  |
| Query  | `queryParam(...)`   | `queryParams(...)`                        | `queryParamMap()` |
| Form   | `formParam(...)`    | `formParams(...)`                         | `formParamMap()`  |

Names are case-sensitive. A submitted empty value is present. A lookup by an absent name returns an empty `Optional`
or list.

Queries and URL-encoded forms use UTF-8 and decode `+` as a space. Path captures keep a literal `+`. Decoding happens
once. A query value of `%2520` becomes the literal text `%20`. The default transport rejects that double-encoded
spelling in a path.

See [path matching](../../routing/patterns/) for pattern syntax and route selection.
For raw text or bytes, see [request bodies](../../bodies/buffered/);
use [multipart fields and files](../../bodies/multipart/) for file uploads.

## Example

The `GET` handler reads the category and search tags,
while the `POST` handler reads tags from a URL-encoded body and reports query tags separately.
Send form input as `application/x-www-form-urlencoded`,
with either no charset parameter or a supported UTF-8 declaration.

The first access to a query value or URL-encoded form field validates the entire query or form. One malformed value
rejects the whole collection, even if you asked for a different name. Shoostr returns `400` for malformed encoding
or too many pairs and `413` when the form body exceeds the size limit. A missing or unsupported content type or an
unsupported charset results in `415`. The transport can reject invalid requests before these accessors run.

## Test

The HTTP tests create the app with `ParametersExample.application()`. `TestServer` starts it on an available loopback
port and shuts it down when the fixture closes.

The tests check that a path like `/search/caf%C3%A9+books` yields `café+books`
and that repeated values keep their order.
They cover decoded names, case-sensitive lookups, empty versus absent values, and separation between form and query
values. The single-decoding test checks `%2520` in a query and its rejection in a path by the default transport.

The invalid input tests check that a malformed value rejects the whole query or form. They also check the `415`
responses for a missing content type, an unsupported media type, or an unsupported charset. Another test checks
that the parameter maps and the query and form value lists are immutable snapshots. See
[request-local state](../state/) for snapshot lifetime and how attribute snapshots differ.
