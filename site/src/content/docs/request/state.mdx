## Description

A request attribute is an application value attached to one live request. It lets an earlier callback prepare information for the endpoint handler without putting that value in global or session state.

A request hook is a callback registered at a named processing phase. This task uses a hook to attach a value and reads it in the handler. The attribute remains limited to that exchange.

Attach values with request attributes so a hook can hand information to its endpoint. Keys are case-sensitive. Reassigning a key replaces its value, and assigning `null` removes it. Bindings belong to one request; they do not provide session state or communication with a later exchange.

Request access is confined to the active handler thread and lifetime.
Do not retain the live `Request` or pass it to another thread; capture needed values and snapshots while handling the request instead.
Parameter, header, and cookie collections are deeply immutable, but `attributeMap()` only copies the bindings: mutable application objects remain shared with the snapshot.
Retaining those objects does not copy them or make them thread-safe.
For an upgraded connection, use the detached values on [WebSocketConnection](../../websockets/managed/) rather than keeping its handshake request.
