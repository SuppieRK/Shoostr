## Description

Header names are case-insensitive. Cookie names are case-sensitive, and Shoostr reads cookie values without URL
decoding. Clients send cookies in the `Cookie` header. Before trusting a request's identity, use
[authentication](../../security/authentication/) to verify credentials from a header or cookie.

The preferences example reads headers and cookies from the handler's `Request` and shows what each accessor returns.

| Source | First value by name | All values for one name, in arrival order | All entries   |
|--------|---------------------|-------------------------------------------|---------------|
| Header | `header(...)`       | `headers(...)`                            | `headerMap()` |
| Cookie | `cookie(...)`       | `cookies(...)`                            | `cookieMap()` |

Case-insensitive header lookup also applies to `headerMap()`. Repeated header field lines keep their order, and a
comma within a field stays part of the value. For example, `first,second` stays a single value.

The cookie accessors treat `theme` and `Theme` as separate names. A value like `a+b%2F` keeps that spelling.
Use `cookies(...)` or `cookieMap()` to see duplicate values for a name.

Reject ambiguous duplicates when a cookie value affects a security decision.

## Example

The `/preferences` endpoint shows all three accessor forms for `X-Label` and the non-security `theme` preference.
It uses `x-LaBeL` to look up `X-Label` in the header map. Use the [response cookie API](../../responses/cookies/) to
set or delete cookies.

Header collections capture construction-time fields after native customization,
and cookie parsing follows the configured transport policy.

The default cookie policy can discard malformed fragments or unquote values,
so do not rely on every malformed cookie being rejected.
Retain a [snapshot](../state/) if you need the values after request handling ends.

## Test

The HTTP tests create the app with `HeadersCookiesExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The tests distinguish empty header and cookie values from missing ones. They verify case-insensitive header lookup,
including map access, and check that repeated field lines keep their order and comma-separated text stays in one
value. The cookie checks cover exact name matching, duplicate names, and percent-encoded text.

Both maps and their value lists are immutable. The tests also check the lists returned by `headers(...)` and
`cookies(...)`.
