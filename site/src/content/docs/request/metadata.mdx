## Description

A request can name an `https` URL over a plain connection. Shoostr exposes the request URI, the direct connection,
and the identity your application assigns as separate values.

This example reads request metadata inside a handler. Choose the accessor based on what you need to know.

| Question | Accessors | What you get |
| --- | --- | --- |
| What method and HTTP version arrived? | `method()`, `protocol()` | Values such as `GET` and `HTTP/1.1`. |
| Which route matched? | `routePattern()` | The registered route template with its placeholders intact. |
| What path did the router use? | `path()` | Jetty's canonical routing path. Its spelling can differ from the encoded URL path. |
| What URL did the transport expose? | `url()`, `fullUrl()`, `queryString()` | `url()` omits the query and fragment. `fullUrl()` keeps the raw query. `queryString()` returns just the raw query, without `?`. |
| What logical destination does the request name? | `scheme()`, `authority()`, `serverName()`, `serverPort()` | The URI scheme, normalized authority, and logical host and port, with transport defaults or fallbacks where applicable. |
| What does the direct connection report? | `localAddress()`, `remoteAddress()`, `isSecure()` | The local and peer socket addresses and whether the direct connection uses TLS. |
| What is the effective client address? | `clientAddress()` | The effective IP socket address, when available. |
| Did Shoostr apply trusted forwarding? | `effectiveUrl()`, `isForwarded()` | The effective full URL and whether Shoostr applied trusted forwarding metadata. |
| What identity did the application assign? | `principal()` | The principal assigned by the application's authentication logic, when present. |

For `/inspect/caf%C3%A9`, `routePattern()` returns `/inspect/{name}`, `path()` returns `/inspect/café`, and
`pathParam("name")` returns `café`. The URL accessors preserve the encoded path spelling.

Check `isSecure()` to determine whether the direct connection uses TLS. Neither the request authority nor the
effective URL establishes a trusted application origin.

## Example

This inspection endpoint reports the metadata without consuming the body or decoding the query.
Keep diagnostic endpoints restricted if you add sensitive application data to their output.

Trusted forwarding is disabled by default. In this example, `effectiveUrl()` equals `fullUrl()`, `isForwarded()`
returns `false`, and `clientAddress()` reports the direct IP peer. Configure [trusted proxy metadata](../../security/proxies/)
when your application needs to use a proxy's forwarding headers.

Use [authentication logic](../../security/authentication/) to verify credentials and assign an identity. The endpoint
reports `anonymous` when no principal has been assigned.

## Test

The HTTP tests create the app with `MetadataExample.application()`. `TestServer` starts it on an available loopback
port and shuts it down when the fixture closes.

A raw-socket test sends an absolute request target starting with `https://docs.example:8443`. Shoostr reports `https`
as the URI scheme and `docs.example:8443` as the authority. The local and remote addresses still describe the plain
socket connection and `isSecure()` returns `false`.

Another test sends `Forwarded`, `X-Forwarded-For`, `X-Forwarded-Proto`, and `X-User`. The effective URL and client
address still reflect the direct request, and the endpoint reports an anonymous caller. The remaining tests compare
raw URL spelling with decoded captures, check that an absent query stays absent, and read a malformed query as raw
text. The URL test selects HTTP/1.1 explicitly before asserting the protocol name.
