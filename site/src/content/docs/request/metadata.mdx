## Description

Use `method()` and `protocol()` for the HTTP method and version, `path()` for the canonical routing path, and `routePattern()` for the selected template before captured values are substituted.
For URL inspection, `url()` excludes the query and fragment, `fullUrl()` preserves the raw query, and `queryString()` returns that query without `?`.
Keep those raw URL accessors separate from decoded parameters: the canonical `path()` can differ from the encoded URL spelling, as `/inspect/caf%C3%A9` does in the test.

The request authority, server name, and server port describe the logical destination, which can differ from `localAddress()` and `remoteAddress()` on the actual connection.
Neither the request authority nor an effective URL establishes a trusted application origin.
Use `isSecure()` for direct transport security: a URI scheme or forwarding header alone does not prove that this connection uses TLS.

## Example

This inspection endpoint reports the metadata without consuming the body or decoding the query.
Keep diagnostic endpoints restricted if you add sensitive application data to their output.

Trusted forwarding is disabled by default, so `effectiveUrl()` equals `fullUrl()` and `isForwarded()` is false.
The effective client address from `clientAddress()` then defaults to the direct IP peer; forwarding headers do not change it without an explicit trust policy.
Configure [trusted proxy metadata](../../security/proxies/) explicitly when the application sits behind a proxy.
Likewise, `principal()` only reads an identity explicitly assigned by [authentication logic](../../security/authentication/)—it does not authenticate credentials or infer a user from headers.
