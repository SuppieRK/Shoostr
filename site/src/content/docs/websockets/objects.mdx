## Description

Decode complete binary WebSocket messages into Java values and encode Java values as replies. A `Codec` supplies
both conversions. Your application defines the payload format and decides which values to accept.
This example uses a codec to exchange counter values over a [managed WebSocket](../managed/).

1. Call `app.codec(codec)` before startup. It returns a `Shoostr.Typed` view for registering routes on the same
application. See [configure a codec](../../json/codec/).
2. Register `routes.websocket(...)` through that view. Its `WebSocket.Typed` configuration provides
`onObject(Class<T>, handler)` for receiving decoded values.
3. Reply with `sendObject(value)` on the `WebSocketConnection.Typed` passed to the callback.

Both directions use the same codec. Ordinary text and byte-array sends bypass it.

:::note[Object messages are binary]
- Object operations use complete binary messages, even when the codec produces JSON.
- Agree on the payload format with the client before exchanging objects.
- `onObject(...)` and `onBinary(...)` share one callback slot. The later registration replaces the earlier one.
`onText(...)` has its own slot for ordinary text messages.
:::

- Typed callbacks follow managed admission, lifecycle and sequential delivery rules.
- A send waits for the transport to finish the write. The peer can receive the message later.
- Shoostr decodes the message before calling the object handler. To catch decode errors for individual messages,
register `onBinary(...)` and decode inside that callback.
- Uncaught conversion exceptions follow managed failure handling. For example, if the codec rejects an invalid payload
with `IllegalArgumentException`, Shoostr closes with `1011` and reports the failure to `onError(...)`.

## Example

The `/counter` endpoint uses four-byte signed integers with the most significant byte first.
In this exchange, it increments the request value and replies in the same format.

| Message | Bytes         | Value |
|---------|---------------|-------|
| Request | `00 00 00 29` | `41`  |
| Reply   | `00 00 00 2a` | `42`  |

The text callback replies to `hello` with `text: hello` and bypasses the codec.
