## Description

Customize the `404` and `405` responses Shoostr generates before it calls an endpoint handler.
This example uses status renderers to supply its own text for each routing error.

| How the status arises                                                                      | Who supplies the response                                                                   |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| The router finds no matching path (`404`) or the path does not support the method (`405`). | The application status renderer, if registered.                                             |
| A `when(...)` condition makes the selected endpoint unavailable (`404`).                   | The local status renderer if configured, with the application status renderer as fallback.  |
| A handler throws `NotFoundException` (`404`).                                              | An [exception renderer](../exceptions/) if registered, or Shoostr's default error response. |
| A handler sets `404` with `response.status(...)`.                                          | The handler supplies the response.                                                          |

Register application renderers with `app.status(status, handler)` before startup. This example uses
`HttpStatusCodes.NOT_FOUND.value()` for `404` and `HttpStatusCodes.METHOD_NOT_ALLOWED.value()` for `405`.
Shoostr sets the status before calling the renderer and preserves the required `Allow` header on `405`.
It rejects a second application renderer for the same status. The [method-routing guide](../../routing/methods/)
explains how Shoostr chooses between those statuses.

## Example

The `path(...)` call groups endpoints under `/reports`. Its configuration callback receives `Lifecycle`,
Shoostr's built-in route and group configuration object. Call `status(...)` on it to register the group's
`404` renderer.

`when(() -> false, ...)` makes `/reports/daily` unavailable after selection. The generated `404` keeps
`Cache-Control: no-store`. The [conditional-routing guide](../../routing/conditions/) explains when
Shoostr evaluates these conditions.

Local status configuration follows the selected endpoint. In this example, a routing miss uses the
application renderer even when the URL starts with `/reports`.

| Request                | Result                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------- |
| `GET /reports/daily`   | `404` with `Report unavailable` from the group renderer.                            |
| `GET /reports/missing` | `404` with `Route not found` from the application renderer.                         |
| `POST /reports/daily`  | `405` with `Method unavailable` from the application renderer. `Allow` lists `GET`. |
| `GET /thrown`          | `404` with the default `Not Found` body for the exception.                          |
| `GET /manual`          | `404` with `Chosen by the handler`.                                                 |
