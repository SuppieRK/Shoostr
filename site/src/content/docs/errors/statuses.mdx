## Description

Some HTTP errors arise before a handler runs. For example, the router can find no matching path or find a path that does not support the requested method. A status renderer customizes the response for those generated statuses.

This task gives router errors a chosen text representation and distinguishes them from a handler-thrown error. `HttpStatusCodes` names HTTP statuses and exposes their numeric values; `NotFoundException` is a handler failure with a not-found status.

Register a renderer with `app.status(status, handler)` for errors generated by routing. The example uses `HttpStatusCodes.NOT_FOUND.value()` for an unknown path and also handles an unsupported method. Shoostr sets the status before invoking the renderer and preserves the required `Allow` field on `405`. The [method-routing guide](../../routing/methods/) explains how the router chooses those statuses.

A status renderer does not handle a thrown exception or run when an endpoint calls `response.status(...)` itself.
Use an [exception renderer](../exceptions/) for a thrown `NotFoundException`, even though it also produces `404`.
Register application status renderers before startup; duplicate registrations for the same status are rejected.

## Example

The application supplies public text for generated `404` and `405` responses, while `/manual` and `/thrown` show the two paths that do not invoke those renderers.
The `path(...)` call groups endpoints under `/reports`. Its configuration callback receives `Extensions`, Shoostr's built-in route and group configuration object. The `lifecycle()` collector registers local request behavior; `status(...)` supplies a generated-status renderer for the group. This built-in configuration requires no installed integration provider.

A `when(...)` condition keeps its routes registered but makes a selected route unavailable when the condition returns false. Here, `when(() -> false, ...)` makes `/reports/daily` unavailable, so a matching GET uses the local `404` renderer and retains `Cache-Control: no-store`. The [conditional-routing guide](../../routing/conditions/) covers conditions and their ordering in more detail.

Local configuration follows the selected endpoint, not just a URL prefix: `/reports/missing` still uses the application renderer.
Likewise, `POST /reports/daily` has no matching endpoint for that method and uses the application `405` renderer.
