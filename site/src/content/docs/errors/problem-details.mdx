## Description

Return API errors as <a href="https://www.rfc-editor.org/rfc/rfc9457.html" target="_blank" rel="noopener noreferrer">Problem Details</a>,
the format defined by RFC 9457. Shoostr's `ProblemDetails` model holds the public fields for the response.
This example registers a JSON codec with `app.codec(codec)` to encode them.

1. Build a `ProblemDetails` with the fields you want to send.
2. Set the HTTP status with `response.status(...)`.
3. Pass `application/problem+json` and the map returned by `toMap()` to the typed `response.body(...)` helper.
   The codec encodes the map.

If you include a `status` member in the body, use the same code in the HTTP response.

- Standard members are optional. `toMap()` omits any you leave unset.
- Extension members appear at the top level. The builder rejects names reserved for standard members.

Write explanations for the client and keep exception messages and internal diagnostics private.

## Example

The handler for `/items/42` throws `NotFoundException`. Its route-scope renderer sets both the HTTP status
and the JSON `status` to `404`. The problem also includes a type, title, public detail, instance URI reference
and numeric `itemId` extension. The renderer passes the map to `response.body(...)`, and `JacksonCodec`
encodes it with Jackson 2's `jackson-databind`.

Choose extension values your JSON serializer can encode. `ProblemDetails` recursively copies extension maps
and lists into unmodifiable containers. Other objects and map keys stay shared with the caller. `toMap()`
returns a fresh, mutable top-level map for encoding.

See [exception handling](../exceptions/) for renderer selection. For codec-backed object conversion, see the
[JSON codec recipe](../../json/codec/).
