## Description

Group related endpoints under a common prefix and configure them once. Child routes inherit the group's configuration.

Use `path(...)` to create a group. Its registration callback receives a `Routes` value for that group.
Pass the same registration method to several groups to reuse the endpoint definitions.
Each prefix is relative to its parent, even when it starts with `/`. A group with the prefix `/v1` inside `/api`
registers routes under `/api/v1`.

Use an empty prefix to share configuration without adding a path segment. To register an endpoint at the group's prefix,
use `get(handler)`. Use `get("/", handler)` for the separate endpoint with a trailing slash.

The configuration callback receives a `Lifecycle` value. Call `beforeRouteHandler(...)` on it to add a request hook
that child routes inherit. The hook runs after route matching and any required authentication, before the endpoint
handler. You can also [register an exception renderer](../../errors/exceptions/) for the group.

## Example

The example uses `notes(...)` to register the same endpoints under `/api/v1/notes` and `/api/v2/notes`.
Both groups inherit the hook that sets `X-API`. The `/api/v2/notes` group adds a hook that sets `X-Version`.
The pathless group sets `X-Group` on `/status`. The `/public` route belongs to the root scope.
The nested account route reads `accountId` from its parent path and `id` from its own path.

Shoostr runs each group's configuration callback before its registration callback. Both run during setup, before the
application starts. The hooks they register run during request handling.

Registration and configuration callbacks run synchronously on the calling thread under the application's shared registration lock.
Registration calls from other threads wait until the complete callback returns, including its nested groups.
Complete registration work on that thread; a callback must not wait for another thread to register routes or close the same application.

Starting the application from a registration callback is rejected.
Closing from another thread waits for the callback to finish before ending registration and starting cleanup.

Route scopes share application-owned registration state and have no separate cleanup operation.

## Test

The HTTP tests create the app with `RouteGroupsExample.application()`. `TestServer` starts it on an available loopback
port and shuts it down when the fixture closes.

The tests send requests to both versions of `/notes` and check that `/api/v1/notes/` reaches a separate handler.
They verify that group headers stay within their scopes and that the account route reads both captures. Requests such
as `/v1/notes` return `404`, confirming that Shoostr resolves `/v1` relative to `/api`.
