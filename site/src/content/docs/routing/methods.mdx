## Description

One path can serve several HTTP methods. Register each method with a handler, the Java callback that prepares the response. In this example, `GET /notes` returns text and `POST /notes` returns `201`.

If no route matches the path, Shoostr returns `404`. If the path matches but none of its routes handles the requested method, Shoostr returns `405` with an `Allow` header.

For ordinary routes, `Allow` lists the registered methods from every complete [path match](../patterns/), including less specific matches.

Customize the generated response with a [status renderer](../../errors/statuses/).

An ordinary `GET` registration handles only `GET`. In the example, `/read-only` returns `405` for both `HEAD` and `OPTIONS`. Register those methods explicitly where you need them.

[Static resource mounts](../../resources/static/) handle `HEAD` for existing files. A [CORS policy](../../security/cors/) can answer an allowed preflight directly with `204`.

Register WebSocket handshakes with the [WebSocket APIs](../../websockets/managed/). Shoostr handles [HTTP/2 extended `CONNECT` for WebSockets](../../websockets/native/) separately from ordinary `CONNECT` routing.

## Example

The example registers seven methods at `/notes` before startup. The `HEAD` handler sets `X-Notes-Mode` and returns an empty body. The `OPTIONS` handler returns `204` and sets `Allow` to the methods registered at `/notes`.

Use `route(...)` for methods without a convenience helper. The example passes the method token `HttpMethods.PROPFIND` to register `/properties`. The string overload accepts recognized, case-sensitive method names. It accepts `"PROPFIND"` and rejects `"get"` and `"FETCH"` with `IllegalArgumentException` during registration.

The HTTP tests create the app with `MethodsExample.application()`. `TestServer` starts it on an available loopback port and shuts it down when the fixture closes.

The tests exercise each registered method, check explicit `HEAD` and `OPTIONS` responses, and distinguish an unknown path (`404`) from an unsupported method (`405`). When `Allow` lists several methods, the tests compare them as a set so header order does not affect the result. Separate registration tests accept `"PROPFIND"` and reject `"get"` and `"FETCH"`.
