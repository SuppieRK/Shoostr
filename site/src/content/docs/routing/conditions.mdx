## Description

A conditional route is registered at startup but considered available only when its condition accepts a request. The condition selects availability; it does not verify credentials or grant permission.

This task uses both an application flag and a request predicate. Nested conditions form part of the route's match, so their order determines whether a later condition is evaluated.

Register availability with `when(...)`. A `BooleanSupplier` reads an application flag; a `Predicate<Request>` evaluates the current request. Nested conditions run from the outer scope inward and stop when one returns false.

Conditions run after route selection and admission, so a false result ends selection with `404` and `Cache-Control: no-store` rather than trying another matching route.
Registration and method discovery remain unchanged: an unavailable route can still contribute methods to a generated `405` response's `Allow` header.
Use these conditions for availability, not as a replacement for authentication or authorization.
