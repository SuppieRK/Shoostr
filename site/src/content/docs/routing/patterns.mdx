## Description

At each path segment, a literal takes precedence over a constrained parameter, an unconstrained parameter, or a catch-all.
The router looks for a route that matches the requested method and the whole path, in this order:

| Pattern              | Match                          |
|----------------------|--------------------------------|
| `/items/latest`      | The literal path               |
| `/items/{id:[0-9]+}` | One segment containing digits  |
| `/items/{name}`      | Any single nonempty segment    |
| `/items/{*tail}`     | One or more remaining segments |

Registration order breaks a tie between overlapping constraints at the same segment. Both routes must match the
requested method and the whole path. `/codes/7` matches both constraints, so the earlier single-digit route wins.
`/codes/12` matches only the one-to-three-digit constraint.

A named parameter captures a segment for the handler. The request exposes the captures from the selected route.

If a more specific pattern fails to match the method or the end of the path, the router can try a less specific route.
If the selected route fails an [availability condition](../conditions/), selection ends with `404`.

Use whole segments for captures and put a catch-all last. It needs a nonempty tail. A constraint supports one ASCII
character class with limited repetition.

Shoostr rejects invalid patterns and equivalent shapes for the same method when you register them. For example,
renaming `{name}` to `{other}` does not make `/items/{name}` a different shape.

## Example

The example registers the broad `/items` patterns before the literal `/items/latest`. A `GET /items/latest` still
selects the literal route. Case and trailing slashes matter. `/status`, `/Status`, and `/status/` are different paths.

The router matches Jetty's canonical path. `pathParam(...)` returns a decoded capture and preserves a literal `+`.
The transport can reject encoded slashes before routing. See [request parameters](../../request/parameters/) for
accessor forms and the decoding differences between paths, queries, and forms.

A catch-all capture is request data. Validate it before using it as a filesystem path.

## Test

The HTTP tests create the app with `PathPatternsExample.application()`. `TestServer` starts it on an available loopback
port and shuts it down when the fixture closes.

The tests cover precedence, registration order for overlapping constraints, and fallback after a method or suffix
mismatch. `DELETE /items/latest` returns `405` with both `GET` and `POST` in `Allow`.

The tests also check decoded captures, case and trailing slashes, and rejection of encoded slashes. Separate registration
tests check that invalid patterns and equivalent shapes are rejected.
