## Description

Content negotiation chooses which response representation to send when a client lists preferences in its `Accept` header. A representation combines bytes with media metadata, such as JSON or plain text.

This task offers several representations of the same result. `MediaType` describes each offered media type, and the selected type tells the handler which body to produce. Negotiation selects a representation; it does not serialize the body for you.

Pass the offered representations to `response.negotiate(...)`. It evaluates the request's `Accept` preferences using quality values and wildcards, retaining server order when preferences tie. With no `Accept` header, the first candidate wins. An explicitly empty list or an unsupported preference yields `406`; malformed syntax yields `400`. Produce the body matching the selected representation after that choice.

Negotiation adds `Accept` to `Vary` without discarding existing fields, including when the result is `406`.
A malformed header fails before this addition.
For the underlying HTTP rules, see [Accept](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1) and [Vary](https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.5).
