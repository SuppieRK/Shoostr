## Description

Bring your own serialization library. Implement `Codec.read(...)` to turn bytes into Java values and
`Codec.write(...)` to encode values for HTTP bodies, WebSocket messages, or SSE events. Your application chooses
the data format and validation rules. This example uses JSON.

Call `app.codec(codec)` and register routes with `.routes(...)` on the returned typed view. Java infers
`Request.Typed` and `Response.Typed` for HTTP endpoint lambdas and scoped `exception(...)` lambdas. The same
view supplies typed WebSocket callbacks and an SSE event writer. Ordinary `app.routes(...)` registrations use
`Request` and `Response`.

| Helper                               | Codec operation     | Result                                                                       |
|--------------------------------------|---------------------|------------------------------------------------------------------------------|
| `request.body(Class<T>)`             | `read(bytes, type)` | Decode the buffered request body to the requested class.                     |
| `response.body(MediaType, Object)`   | `write(value)`      | Encode an object and stage its bytes with explicit media metadata.           |
| `response.body(String, Object)`      | `write(value)`      | Encode an object and stage its bytes with a media type supplied as a string. |
| `socket.onObject(Class<T>, handler)` | `read(bytes, type)` | Decode a complete [binary WebSocket message](../../websockets/objects/).     |
| `connection.sendObject(Object)`      | `write(value)`      | Encode and send a [binary WebSocket message](../../websockets/objects/).     |
| `events.sendObject(Object)`          | `write(value)`      | Encode UTF-8 text as [SSE event data](../../streaming/sse-objects/).         |

`response.body(MediaType.APPLICATION_JSON, user)` sets the response media type to `application/json` and calls the
codec to encode `user`. Typed handlers can still use `text(...)` and `body(..., byte[])` without calling the codec.

The read helper takes a `Class<T>`, so it cannot express a parameterized type such as `List<User>`. If your codec
supports `User[]`, you can read a JSON array with `request.body(User[].class)`.

- Configure the codec before registration and keep it safe for concurrent HTTP handlers and WebSocket callbacks.
  Your application owns any codec cleanup.
- Each typed HTTP body read decodes the bytes again. The [buffered request-body limits](../../bodies/buffered/)
  still apply.
- Shoostr checks the finite HTTP response-byte limit after encoding. WebSocket and SSE object sends are outside
  that limit.
- Transport buffering cannot bound allocations or execution time inside the codec.

## Example

`POST /users` returns the validated user as JSON with status `201`. `/help` uses ordinary text output.

The codec uses Jackson 2's `jackson-databind`. It calls `readValue(...)` for the requested class and
`writeValueAsBytes(...)` for the outgoing object. Jackson maps the `User` record without annotations, and the
record constructor requires a nonblank name.

The codec reports malformed JSON and invalid input as `BadRequestException`. The scoped exception handler uses
the same codec to write an error map as a JSON `400` response. Use [exception renderers](../../errors/exceptions/)
for shared error handling or return [Problem Details](../../errors/problem-details/) when clients need a standard
error format.

The handler selects JSON output explicitly. The example accepts valid user JSON regardless of the request's
`Content-Type` and sends JSON regardless of `Accept`. Set your own input media policy and use
[content negotiation](../negotiation/) when a response needs to match the client's preferences.

## Test

The HTTP tests create the app with `JsonCodecExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The tests check Unicode and escaping in the returned JSON, a JSON `400` for malformed or invalid input, and the
plain-text response from `/help`. They also send valid JSON with `Content-Type: text/plain` and
`Accept: application/xml` and check that the example still returns JSON with status `201`.
