## Description

Serve Swagger UI locally so readers can explore your OpenAPI document in a browser. Register the page, the assets and the
generated JSON specification on separate routes. If the API description is private, protect all three registrations.

:::note[Libraries required]
- `io.github.suppierk:shoostr-openapi` provides the OpenAPI document and the local UI handler.
- `io.github.suppierk:shoostr-pac4j` provides the pac4j adapter for route authentication.
- `org.pac4j:pac4j-http` provides the `DirectBasicAuthClient` used for Basic authentication in this example.

See [Maven and Gradle installation](../../start/libraries/) for published Shoostr coordinates.
:::

Create an `OpenApi` instance and select it with `withExtension(docs)` on the operations you want to describe. The first
selection sets up document generation. Create the UI handler with `docs.uiHandler("/docs/", "/openapi.json")`, then add
these GET routes.

1. Serve `docs.handler()` at `/openapi.json`.
2. Serve the UI handler at `/docs/`, with the trailing slash.
3. Reuse the UI handler on the asset catch-all `/docs/{*asset}`.

The UI handler serves four prepared resources. These are the HTML page at `/docs/`, `swagger-ui.css`,
`swagger-ui-bundle.js`, and `swagger-initializer.js`. Other asset paths return `404`. Shoostr bundles the stylesheet
and JavaScript locally and disables the external specification validator.

This example selects the same `Pac4j` instance in the specification route and the UI group's `Lifecycle` callbacks.
Shoostr sets up the adapter on first selection. The group's authentication applies to both the page and the asset route.
The configured Basic client verifies credentials before Shoostr serves those resources.

The fixed credentials are for local testing. For deployment, use a real credential verifier and HTTPS.
See the [pac4j recipe](../../security/pac4j/).

## Example

`GET /me` has its own route authentication. The OpenAPI security declaration tells the UI which credentials the
operation expects.

- Use **Authorize** to supply API credentials explicitly. Enter them again after reloading the page.
- The same-origin specification request can use the documentation login. API calls omit browser cookies and cached
  HTTP credentials.
- Use a separate client for API operations that require browser session cookies.

Use literal, same-origin paths for the UI and the specification. If the UI group inherits documentation defaults,
call `hidden()` in its `OpenApi` configuration to omit the page and its catch-all from the document.
For schemas and operation metadata, see [describe HTTP operations with OpenAPI](../documents/).

## Test

The tests start `OpenApiUiExample.application()` with `TestServer` on an available loopback port. The fixture owns
application shutdown. The tests check the Basic challenge on the page, every asset and the specification, and check
credential rejection and acceptance on `/me`. They retrieve the local assets, check `404` for an unknown asset, and
inspect the initializer and the generated security declaration.

The JavaScript bundle exceeds the default finite-response limit in `Options`. The test retrieves it successfully
with the default settings because the UI handler streams the asset. These checks cover HTTP responses and
initializer settings. Browser execution of Swagger UI is outside their scope.
