## Description

Publish an OpenAPI document so readers and tools can see your API's operations, parameters and representations.
The application still implements those operations, validates input, selects codecs and enforces access rules.
Each document describes the routes that select its provider. Configure access separately for the operations and
for each document URL. See the [OpenAPI 3.1.1 specification](https://spec.openapis.org/oas/v3.1.1.html).

:::note[Libraries required]
- `io.github.suppierk:shoostr-openapi` provides `OpenApi` and brings in the Swagger model classes.
- `tools.jackson.core:jackson-databind` is the Jackson 3 library the example uses to read and write JSON. The provider already includes it as a dependency.

See [Maven and Gradle installation](../../start/libraries/) for published Shoostr coordinates.
:::

Shoostr's `OpenApi` provider collects explicit operation descriptions from registered routes. This example describes
an item API and serves its document alongside a separate operations document.

1. Create an `OpenApi` instance and register reusable schemas as explicit Swagger `Schema` models.
2. Select it with `lifecycle.withExtension(docs)` in the route or group's `Lifecycle` callback. Set operation metadata on the
   returned `OpenApiOperation`. The first selection installs the provider automatically.
3. Register `docs.handler()` on its own GET route to serve the JSON document.

The provider builds the document from registered route metadata and your explicit models. Supply schemas and media types
even when the handler uses a codec.

Shoostr checks the published operations during startup.

- Declare every path parameter by its exact template name and mark it required.
- For a constrained parameter, supply an inline schema whose only type is `string`. Shoostr rejects references and
  content-based declarations for these parameters. The published schema requires both the route constraint and any
  pattern already in the schema.
- A published catch-all route, unsupported HTTP method, missing path parameter declaration, duplicate operation identifier
  or ambiguous operation path prevents startup.
- Shoostr checks known local component references against the document. It preserves external references and other JSON
  Schema references as supplied. Use a separate validator for full JSON Schema validation or reference resolution.

An endpoint starts with its own copy of any group defaults. Changes to that copy follow these rules.

| Field | Effect of setting it in a child scope |
| --- | --- |
| Summary, description, operation identifier | Replace the inherited value for that field. |
| Tags | Add tags and keep each name once. |
| Parameters | Replace the parameter with the same name and location. Other parameters stay available. |
| Responses | Replace the response with the same status. Other statuses stay available. |
| Request body, security | Replace the entire inherited declaration for that field. |

For the configuration methods, see [OpenApiOperation](https://github.com/SuppieRK/Shoostr/blob/main/openapi/src/main/java/io/github/suppierk/shoostr/openapi/OpenApiOperation.java).
The generated JSON must fit the application's finite-response byte limit. The optional UI sends its assets using bounded streaming.

## Example

The item API reuses the `Item` schema for JSON requests and responses. The GET route declares its numeric `id`
parameter, and `POST /api/items` checks the input itself. It returns `400` for malformed JSON, a missing, non-string or
blank name, or trailing JSON values. `GET /operations/status` selects a second `OpenApi` instance and appears only in
the document at `/internal-openapi.json`. The item operations appear in `/openapi.json`.

Generation uses route metadata before the listener starts. The document handler then serves the same JSON bytes.
Document generation leaves handler execution and availability checks to real requests. A conditional route stays in the
document even while unavailable. Use `hidden()` to omit a selected route or group.

Protect a document URL explicitly when it describes private operations. The [OpenAPI UI guide](../ui/) covers protecting
the page, assets and document together.

## Test

The tests start `OpenApiDocumentExample.application()` with `TestServer` on an available loopback port. The fixture owns
application shutdown. The tests inspect the generated operations and schemas, call the GET and POST handlers, check
`400` responses for invalid input, and verify which operations appear in each document.

A separate fixture changes a schema after registration and checks that the document keeps the registered copy. It also
checks that startup freezes configuration, repeated requests return identical document bytes, and `/preview` is documented
before any availability check or handler invocation occurs. A real request to `/preview` returns `404`.
