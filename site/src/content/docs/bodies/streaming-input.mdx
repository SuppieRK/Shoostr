## Description

Process a request body as it arrives, without holding the whole body in memory. This example updates a checksum
as it reads each chunk.

Use streamed input when the handler can process data in chunks. Use a [buffered body](../buffered/) when it needs
the complete text or byte array.

Open the stream with `input()` and process bytes as you read them. Calling `input()` again returns the same stream
at its current position.

Once you select streamed input, switching to buffered reads or multipart parsing throws `IllegalStateException`.

Read the stream on the handler's thread during the request-handling lifetime. Shoostr closes the stream during
request finalization.

Bytes you read or skip count toward the configured request-byte limit. Opening the stream or stopping early leaves
the unread part of an unknown-length body unchecked by that limit.

To read a fixed-size prefix, call `input().readNBytes(n)`. It returns as soon as it reads `n` bytes or reaches
the end of the body. A valid zero-length `read(...)` returns `0` immediately, even at the end of the stream.

## Example

The endpoint computes SHA-256 with a per-request digest and a bounded transfer buffer. It returns the checksum
after reading the entire body successfully.

The example uses the default 1 MiB input limit. Shoostr returns `413` before the handler runs if the declared
length exceeds that limit. For an unknown-length body, reading past the limit fails and produces `413`.

See [buffered bodies](../buffered/) for the body-mode comparison and [server options](../../application/server-options/)
for general limit configuration.

## Test

The HTTP tests create the app with `StreamingInputExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The tests check known checksums for empty input, `abc`, and a body larger than the transfer buffer. Both
fixed-length and chunked requests succeed at exactly 1 MiB and return `413` with one extra byte.

Test-only handlers check that calling `input()` again returns the same stream and the next read picks up where
the previous one stopped. They also check that buffered text, bytes, URL-encoded form reads, and multipart
parsing throw `IllegalStateException` after streaming access starts.
