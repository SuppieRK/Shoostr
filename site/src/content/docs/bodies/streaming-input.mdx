## Description

Calculate an upload checksum with `input()` as bytes arrive, without building a whole-body byte array.
Repeated calls return the same stream at its current position; they do not restart the body.
Once streamed input is selected, buffered reads and multipart parsing are unavailable for that request.

The stream belongs to the active handler and is closed during framework finalization, so finish reading within that lifetime rather than handing it to detached work.
The configured request-byte limit applies as bytes are consumed, including skipped bytes.
Opening a stream or stopping early does not validate the unread remainder of an unknown-length body.

## Example

The endpoint calculates SHA-256 with a per-request digest and a bounded transfer buffer, then returns the checksum only after successful consumption.
It uses the default 1 MiB input limit; excessive declared length is rejected before the handler, while an unknown-length overflow produces `413` during reading.
See [buffered bodies](../buffered/) for the body-mode comparison and [server options](../../application/server-options/) for general limit configuration.
