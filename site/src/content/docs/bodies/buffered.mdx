## Description

A request body is the data sent after the HTTP headers. A buffered read collects that data before the handler uses it, which suits a bounded text or byte payload. The `Request` passed to the handler supplies those reads; the handler's `Response` supplies the reply.

This task reads the same input as bytes and text. `Options` sets the buffered-byte limit, and `MultipartOptions` configures multipart limits separately. A `MediaType` describes the representation sent back to the client.

Call `bodyBytes()` for bytes or `bodyText()` for UTF-8 text. Shoostr caches buffered input and returns an independent copy for each byte-array result. To decode with another charset, use `bodyText(Charset)`; this leaves the cached bytes and byte limit unchanged. The methods do not select a charset from `Content-Type`. Malformed text uses the selected charset's replacement behavior, whereas URL-encoded forms require strict UTF-8. For a Java model, continue with a [JSON codec](../../json/codec/).

Choose one body mode for each request:

| Mode      | Accessors                                                                 | Reading behavior                                  |
| --------- | ------------------------------------------------------------------------- | ------------------------------------------------- |
| Buffered  | `bodyText()`, `bodyText(Charset)`, `bodyBytes()`, URL-encoded form fields | Cached input supports repeated reads              |
| Streaming | `input()`                                                                 | One bounded stream advances as bytes are consumed |
| Multipart | Multipart fields and file accessors                                       | Parsed parts remain scoped to the request         |

Do not combine these modes, except that URL-encoded form access shares the buffered body.
A file lookup on a nonmultipart request returns empty without claiming its input.

## Example

The `/text` endpoint reads UTF-8, `/latin1` selects ISO-8859-1 explicitly, and `/bytes` preserves the input bytes, while `/form` reads both the original body and its decoded fields.
See [request parameters](../../request/parameters/) for ordinary query and form access.

This example sets a 64-byte request limit and a four-pair limit for each query or URL-encoded form.
Oversized declared input is rejected before the handler, and a buffered read also enforces the byte limit when the length is unknown.
Byte overflow produces `413`; pair overflow produces `400`, counting repeated names as separate pairs rather than merging the query and form totals.
