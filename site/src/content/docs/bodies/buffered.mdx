## Description

Read the same request body as bytes or as text. Shoostr buffers the input up to the byte limit set in `Options`
and reuses the cached bytes for later reads in the same request.

Call `bodyBytes()` for an independent byte array on each read or `bodyText()` for UTF-8 text.

Use `bodyText(Charset)` to decode with another charset. The cached bytes and the byte limit stay the same.
The text methods do not select a charset from `Content-Type`.

Text decoding replaces malformed input according to the selected charset. URL-encoded form reads require strict
UTF-8. To read a body into a Java object, use a [JSON codec](../../json/codec/).

Choose one body mode for each request.

| Mode      | Accessors                                                                 | Reading behavior                                  |
|-----------|---------------------------------------------------------------------------|---------------------------------------------------|
| Buffered  | `bodyText()`, `bodyText(Charset)`, `bodyBytes()`, URL-encoded form fields | Cached input supports repeated reads              |
| Streaming | `input()`                                                                 | One bounded stream advances as bytes are consumed |
| Multipart | Multipart fields and file accessors                                       | Parsed parts remain scoped to the request         |

URL-encoded form access uses the same buffered body as the text and byte methods.
A file lookup on a non-multipart request returns empty without claiming its input.

## Example

The `/text` endpoint reads UTF-8, `/latin1` selects ISO-8859-1 explicitly, and `/bytes` sends the input bytes back.
The `/form` endpoint reads the original text and the decoded form fields from the same buffered body.
See [request parameters](../../request/parameters/) for ordinary query and form access.

This example sets a 64-byte request limit and a four-pair limit in `Options`. The pair limit applies separately to
the query and to a URL-encoded form. Each occurrence of a repeated name counts as its own pair.

| Situation | Result |
| --- | --- |
| Declared body length exceeds 64 bytes | Shoostr rejects the request with `413` before the handler runs. |
| Body length is unknown and a buffered read exceeds 64 bytes | The read fails and Shoostr returns `413`. |
| The query or URL-encoded form has more than four pairs | Shoostr returns `400` when the handler reads the parameters. |

## Test

The HTTP tests create the app with `BufferedBodyExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The tests check that binary input comes back byte for byte, text uses UTF-8 by default or the explicit ISO-8859-1
charset, and each returned byte array is independent. They read raw text and decoded form fields from the same
body. A text read replaces malformed UTF-8. A form read rejects it with `400`.

The tests accept 64 bytes and reject 65 with `413`, even on a route that leaves a declared body unread. A
multibyte input confirms that the limit counts bytes. Four pairs in the query and four in the form pass together.
Adding a fifth pair to either source returns `400`.

The body-mode tests verify that switching to streaming or multipart access after buffering fails, and that a file
lookup on a non-multipart request leaves the body available to read.
