## Description

Use `shoostr-opentelemetry` with an application-configured OpenTelemetry SDK, including the propagators, sampler and exporters your application needs.
Install `OpenTelemetryTracing`, then select `extensions.with(tracing)` on a route or group to create SERVER spans there.
Installation alone does not create those spans. Select tracing in `app.configureExtensionsDefaults(...)` for registered endpoints by default, and use `extensions.without(tracing)` for a local exclusion.
Configure `allRequests()` before installation when unmatched requests and pre-routing work also need coverage; that application-wide observation is outside scoped exclusion.

Incoming context is extracted through the supplied propagator, so [W3C Trace Context](https://www.w3.org/TR/trace-context/) fields `traceparent` and `tracestate` depend on that SDK configuration.
The adapter makes the server span current during invocation and explicitly reattaches it across a selected [endpoint executor](../../lifecycle/executors/), restoring the worker's previous context afterward.
Application-created asynchronous tasks still need their own SDK context propagation rather than inheriting permission to use live request objects.
The [OpenTelemetry context propagation guide](https://opentelemetry.io/docs/concepts/context-propagation/) explains how this context connects operations across service boundaries; trace headers are correlation data, not authentication.

## Example

The item route selects tracing and creates a `load-item` child operation beneath its current server span on the supplied worker.
`/health` selects no SERVER observation and reports whether any span is current; with empty admission context it returns `traced=false`.
Selective installation carries admission SDK context across unselected handoffs too, without creating SERVER spans there or suppressing application-created spans.

Completed server spans use the composed method and route template, with terminal status and bounded error attributes rather than raw paths, credentials or exception events.
Transport failures, 5xx responses and uncommitted application failures set an error status; a handled 4xx does not become an error solely because an exception produced it.
The SDK controls sampling and export, and the adapter neither installs a global SDK nor closes the borrowed SDK or worker pool.
