## Description

Trace a selected HTTP endpoint and follow its context onto a worker. A trace connects operations across services.
A server span represents this application's part of the request, and child spans represent work it performs.
The example uses `OpenTelemetryTracing` with an SDK your application owns.

Configure tracing and select where it runs.

1. Configure your OpenTelemetry SDK's propagators, sampler and exporters in application code.
2. Pass that SDK to `new OpenTelemetryTracing(telemetry)` from `shoostr-opentelemetry`.
3. In a route or group configuration callback, select the provider with `lifecycle.withExtension(tracing)` on the
   supplied `Lifecycle`. Shoostr sets up the shared extension automatically.
4. For application-wide defaults, call `app.withExtension(tracing)` before registering routes. Use
   `lifecycle.withoutExtension(tracing)` for local exclusions.

Extension selection creates `SERVER` spans only for selected endpoints. Unmatched requests produce no spans from the extension.

The provider carries trace context through request handling.

- It extracts incoming context with the SDK's configured propagator. To read `traceparent` and `tracestate`, configure
  the W3C propagator. [W3C Trace Context](https://www.w3.org/TR/trace-context/)
- It makes the server span current during invocation, attaches it on the selected worker, and restores the worker's previous
  context when the invocation ends. See [endpoint execution](../../lifecycle/executors/).
- For asynchronous tasks you start yourself, propagate context with the SDK and pass detached values to the task.
  Live requests and responses stay with the active request owner. [OpenTelemetry context propagation](https://opentelemetry.io/docs/concepts/context-propagation/)

Use trace headers to correlate operations. Authenticate the caller separately.

Use the [Maven and Gradle installation guide](../../start/libraries/) for the published integration coordinates.

## Example

Both routes run on the supplied executor.

| Route | Behavior |
| --- | --- |
| `GET /api/items/{id}` | Selects tracing and creates a `load-item` child span under the current server span. |
| `GET /health` | Reports whether a valid span is current. With empty admission context it returns `traced=false`. |

The shared setup carries the SDK context captured during request admission onto the worker for `/health` too.
The route can use that context for its own spans. Only the item route selects a server span from the provider.

The provider finalizes server spans when the request terminates.

- The span name combines the HTTP method and the composed route template, such as `GET /api/items/{id}`.
  The provider records the committed HTTP status when available. It omits raw request paths, credentials and exception events.
- A transport failure, a 5xx response or an application failure with no committed response sets the span status to
  `ERROR`. The `error.type` attribute uses `transport`, the 5xx status code or `application`, in that order.
  A handled exception that produces a 4xx response leaves the span status unset unless the transport also fails.

Sampling and export follow the SDK you pass in. Configure any global SDK separately. Keep the borrowed SDK and worker pool
available through application shutdown and until any outstanding work that uses them finishes. Close them yourself.

## Test

The tests start `RequestTracingExample.application(telemetry, workers, options)` with `TestServer` on an available
loopback port. The fixture owns application shutdown. The tests collect detached `RequestOutcome` summaries through
`afterRequest(...)` and wait for them before checking finished spans.

The tests use `opentelemetry-sdk` and the in-memory exporter from the test-scoped `opentelemetry-sdk-testing` library.
They cover both platform and virtual application execution modes.

- The server span continues the incoming W3C parent. `load-item` is a child of that server span. The worker has no valid current span after the request.
- `/health` exports no spans. After Shoostr closes, the worker still accepts tasks and the SDK exports a new application span.
- With the test SDK's default sampler, an unsampled remote parent produces no exported spans. The endpoint still returns its item.
- A failed request exports an `ERROR` server span with status `500` and no secret attributes or exception events.

Backend ingestion is outside these checks.
