## Description

This first application answers `GET /hello` with `Hello, Shoostr!` as plain text. Follow one request from registration to its handler, then verify the response over HTTP.

A `Shoostr` instance is the application: it holds the serving configuration and the routes registered before startup. A **route** associates an HTTP method and path with a **handler**, the Java callback that performs the work. Shoostr passes that callback a `Request` for incoming data and a `Response` for the outgoing status, headers and body.

Here, `routes(...)` supplies the registration view, `get(...)` binds the GET path, and `response.text(...)` prepares the text response. No additional integration is needed for this endpoint.

Use Shoostr core in a Java 21 project with your existing SLF4J logging configuration. The [library reference](../libraries/) covers application and test dependencies when you need it. Public interfaces can change.

## Example

The complete class below separates configuration from startup. `application()` returns an unstarted application; `main(...)` starts its listener. Constructing the application also registers its JVM shutdown hook, so normal JVM shutdown closes a launched application. A caller managing an instance directly must close it, including an instance that never starts.

The default listener accepts traffic on all IPv4 interfaces at port `8080`, rather than only on loopback. The HTTP test below uses its own loopback listener.

## Test

`TestServer` is Shoostr's HTTP test fixture. It starts the configured application on an available loopback port and owns its shutdown. The test sends a real request to `/hello` and checks the status, text and content type. `HttpHeaders` supplies named HTTP header constants used by the assertion.

The application and test are shown as complete Java classes throughout these guides. The test exercises the same application factory as the launcher, so the behavior being explained is also the behavior being checked.
