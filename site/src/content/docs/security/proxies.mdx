## Description

Configure `trustedProxies(...)` with the addresses of proxies you control and one `ForwardedHeaders` family before startup.
Shoostr checks the physical peer before interpreting forwarding metadata, ignoring those assertions when the peer is untrusted.
`RFC7239` selects the standardized [Forwarded field](https://www.rfc-editor.org/rfc/rfc7239.html), while `X_FORWARDED` selects the legacy X-Forwarded fields; assertions from the other family are not merged into the result.

The trust walk proceeds from the rightmost entry through known proxies and stops at the first untrusted node rather than accepting an arbitrary leftmost address.
Your edge proxy must remove untrusted forwarding input or append truthful entries, because trusting its address does not make client-supplied assertions true.
Malformed selected metadata from a trusted peer receives `400`; any supplied legacy host, protocol, or port lists must align with the X-Forwarded-For hop count.

## Example

The factory captures a peer-address snapshot and the chosen family, then exposes `clientAddress()` and `effectiveUrl()` at `/metadata`.
These are proxy-aware values, unlike the [direct request metadata](../../request/metadata/) used to describe the transport itself.

`isSecure()` reports actual transport TLS only.
`isEffectivelySecure()` instead uses an explicitly trusted forwarding protocol when present and otherwise falls back to transport TLS; an effective URL scheme alone is not proof of security.
This distinction matters when a trusted proxy receives HTTPS but forwards to Shoostr over HTTP, and is the security accessor used by the [pac4j adapter](../pac4j/).
