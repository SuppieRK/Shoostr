## Description

Use Cross-Origin Resource Sharing (CORS) to tell browsers which origins can read your responses and what
they can send after a preflight. Verify callers separately with [authentication](../authentication/).

1. Build a `CorsPolicy` with the allowed origins, methods and request headers. Pass it to `new Cors(policy)`.
2. In a route or group configuration callback, use the supplied `Lifecycle` to call
   `lifecycle.withExtension(cors)`. Shoostr handles shared setup on first selection.
3. To use the policy as the application default, call `app.withExtension(cors)` before registering routes.
   Call `lifecycle.withoutExtension(cors)` for a route or group you want to exclude.

A group passes its selection to registered descendants, including static mounts and SSE routes. An endpoint
registered separately uses its own scope even when its URL starts with the group's prefix.

- A child inherits the full policy. Replace it with `lifecycle.withExtension(cors).policy(replacement)`.
- A replacement uses its own defaults for omitted settings and its own collections for origins, methods
  and headers. The parent and sibling policies stay in effect in their scopes.
- Select the same `Cors` instance when replacing a policy or restoring protection after an exclusion.
  Repeated selection keeps one contribution. If you call `policy(...)` more than once, the last complete policy wins.

| Setting | Standalone default and constraints |
| --- | --- |
| Origins | None. Use exact origins with a scheme and any nondefault port. Omit the path and trailing slash. |
| Methods | `GET` and `HEAD`. An empty set permits no methods. `allMethods()` permits any valid method token. |
| Allowed request headers | None beyond the browser's safelisted request headers. |
| Exposed response headers | None beyond the browser's safelisted response headers. |
| Credentials | `false`. For credentialed sharing, use exact origins and name any headers you expose. |
| Maximum age | Five seconds. Use `0` to disable browser preflight caching. |

An origin or header wildcard takes the place of every other value in its collection. Preflight replies list the
validated requested method and headers, including for wildcard methods and request headers. See the
[Fetch CORS protocol](https://fetch.spec.whatwg.org/#http-cors-protocol).

A browser preflight sends `OPTIONS` with `Origin` and `Access-Control-Request-Method`. The browser omits
credentials. See the [Fetch credential rules](https://fetch.spec.whatwg.org/#cors-protocol-and-credentials).

- Shoostr looks up the target using the requested method before authentication, CSRF and native session processing.
- An admitted preflight returns `204` with the configured cache lifetime and required `Vary` fields. Shoostr
  handles it without an `OPTIONS` handler.
- Application header-admission hooks still run. An admitted preflight skips authentication, CSRF, native session
  processing, target conditions, local hooks and the target handler.

| Preflight result | Status |
| --- | --- |
| The registered target's policy permits sharing | `204` |
| The registered target's policy denies sharing, or the target has no CORS policy | `403` |
| Malformed CORS fields | `400` |
| No target for the requested path or method | Normal `404` or `405` |

Shoostr checks actual cross-origin requests even after a cached preflight. Denied permissions yield `403` before
the handler and grant no sharing. Malformed CORS input yields `400`. Once CORS admits an actual request,
authentication failures and framework-rendered errors keep the applicable sharing and `Vary` headers, including
after a response reset.

Requests without `Origin` and same-origin requests follow normal routing. Ordinary `OPTIONS` requests use their
own route and its policy. Excluding CORS from a route leaves ordinary HTTP access in place and removes automatic
sharing and origin-based rejection for actual requests. Protect cookie-backed writes with [CSRF](../csrf/).
Validate browser origins for WebSockets with a [handshake Origin check](../../websockets/managed/).

Builder collection methods take a required first value and optional additional arguments. Pass a set for
computed or explicitly empty collections. Each call replaces that setting, and `build()` validates the complete policy.
`new Cors(policy)` and scoped replacement validate and copy the supplied policy. The scope configurator accepts
changes only during registration.

| Accessor | Configured headers |
| --- | --- |
| `policy.allowedHeaders()` | Request headers permitted during preflight. |
| `policy.exposedHeaders()` | Additional response headers browser scripts may read. |

Both accessors return immutable sets of `HttpHeaders`. Use `cors.policy()` for a defensive copy of the owner's
base policy. Keep a replacement policy in a variable if another part of your application needs its header names.

## Example

The application policy shares responses with `https://app.example` for `GET` and `POST`. It lets preflights
request `Authorization` and `Content-Type`, and lets scripts read `X-Request-Id` on actual responses.
It enables credentialed sharing and sets a 600-second preflight cache lifetime.

| Scope | Policy |
| --- | --- |
| Application defaults, including `/messages` | Uses the application policy above. |
| `/reports` group | Replaces the default with `https://reports.example` and the `X-Report-Format` request header. Credentialed sharing and preflight caching are off. |
| `/health` | Excludes CORS and remains accessible over ordinary HTTP. |
| Separately registered `/reports/outside` (test fixture) | Uses the application defaults. |

The report endpoint returns `403` to the application origin. The messages endpoint returns `403` to the report origin.

## Test

The tests start `CorsExample.application()` with `TestServer` on an available loopback port. The fixture owns
application shutdown.

- Preflight tests check the response fields, complete policy replacement and rejected methods, origins and headers.
- Routing tests check that missing targets receive no sharing grant. They also check the health exclusion and
  application defaults on a separately registered route.
- An authentication fixture throws `AuthenticationRequiredException` on the actual request. Preflight succeeds,
  then the actual request receives `401` with the sharing headers.

These HTTP tests check server status and headers. Browser enforcement and cookie delivery require browser tests.
