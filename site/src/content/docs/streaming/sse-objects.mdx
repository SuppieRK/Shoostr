## Description

Object events combine server-sent event framing with application-provided serialization. A `Codec` converts a Java value to bytes; the typed event writer places its UTF-8 text into an SSE data frame.

This task uses the typed route-registration view returned after configuring that codec. `TypedResponse` is the response view carrying that codec. Its `TypedEventStream` adds `sendObject(...)` to the ordinary event operations. Encoding a value does not add event history or replay behavior.

Register `routes.sse(...)` on the typed view obtained from a configured [codec](../../json/codec/). `TypedResponse.startEventStream()` supplies a `TypedEventStream`; `sendObject(value)` encodes the value before adding data fields and flushing its event. Ordinary strings, `SseEvent` values, comments and heartbeats bypass the codec. The [base SSE guide](../sse/) explains names, IDs and replay.

:::note[Object events require UTF-8 text]
Use a codec that produces UTF-8 text, such as JSON, for SSE object output.
Unlike binary WebSocket messages, an SSE event cannot carry an arbitrary binary serialization directly.
The client still receives text event data and must decode that representation itself.
:::

Malformed UTF-8 or a codec failure writes no part of that event, but `startEventStream()` has already committed the HTTP headers and any earlier events remain sent.
The writer belongs to the handler thread and cannot be retained after the handler returns; the [streaming lifetime and backpressure rules](../output/) also apply.

## Example

The `/progress` endpoint sends `Progress(10)` and `Progress(100)` as JSON data events, with an initial comment and a heartbeat between the data frames.
Its output-only codec supports this numeric model, not arbitrary JSON objects, and the record constructor rejects percentages outside `0`–`100`.
