## Description

Send a Java value as SSE data. Your `Codec` encodes the value as bytes, and the event writer reads those bytes
as UTF-8 before framing the text as an SSE event. This example sends progress updates as JSON.

1. Call `app.codec(codec)` before startup. It returns a `Shoostr.Typed` view for registering routes that use
   the codec. See [configure a codec](../../json/codec/).
2. In that view's `.routes(...)` callback, register the GET endpoint with `routes.sse(...)`.
   The handler receives a `Response.Typed`.
3. Call `response.startEventStream()` to get a `Response.EventStream.Typed`.
4. Call `sendObject(value)` to encode the value, write the data fields and flush the event.

The same writer accepts strings, `SseEvent` values, comments and heartbeats. Those calls bypass the codec.
The application still owns event history and replay. See the [SSE guide](../sse/) for names, IDs and replay.

:::note[Object events require UTF-8 text]
Use a codec that produces text, such as JSON. Encode binary values as UTF-8 text before sending them as
events. The client parses that representation from the event data.
:::

- `sendObject(...)` writes the event only after the codec succeeds and its output passes UTF-8 validation.
- `startEventStream()` has already committed the HTTP headers. Any events sent before an encoding failure
  remain sent.

Use the writer on the handler thread while the handler is active.
See the [streaming lifetime and backpressure rules](../output/).

## Example

The `/progress` endpoint sends four frames in order.

1. The comment `ready`.
2. `Progress(10)` as JSON data.
3. A heartbeat.
4. `Progress(100)` as JSON data.

`ProgressCodec` encodes only `Progress` values because this endpoint sends a single kind of update.
The record accepts percentages from `0` through `100`.
