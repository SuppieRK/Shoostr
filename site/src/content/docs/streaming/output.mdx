## Description

Send output while the handler is still running. Write chunks through `response.startStream(...)` or pass an input
source to `response.input(...)`. Both bypass the finite-body size limit and use a bounded output buffer.

The buffer capacity limits how many bytes can be pending at once. A large transfer can flush and reuse that buffer
for as long as the handler and transport keep the stream open.

- The buffer grows as needed up to its default capacity of 8 KiB (8,192 bytes) and flushes automatically when full.
- Call `flush()` to send pending bytes before the buffer fills. Either kind of flush waits until the transport
  has finished using the buffer. That wait applies backpressure to the handler. The bytes can reach the client later.
- Shoostr sends any remaining bytes when the handler returns.
- To change Shoostr's buffer capacity, call `options.setStreamBufferBytes(16_384)` before constructing
  `new Shoostr(options)`. Jetty's native output-buffer settings apply at the transport layer.
  See [application settings](../../application/server-options/).

Starting a stream commits the selected status and headers. If a failure occurs after commitment, Shoostr aborts
the transfer. See [exception recovery](../../errors/exceptions/).

- Set the status and headers before starting the stream.
- Select one output mode per response. Use [finite response bodies](../../responses/bodies/) for replaceable output
  or [file downloads](../../resources/downloads/) to stage a transfer from a path.
- `Stream.write(String)` always encodes as UTF-8. To use another charset, declare it in the content type,
  encode the text yourself and write the resulting bytes.

## Example

The `/chunks` handler flushes the CSV header before writing two records. The `/input` handler opens the report
and passes the source to `response.input(...)`. That call closes the source when it exits, including if reading
or writing fails.

- Use the response and stream on the handler thread while the handler is active. Shoostr owns response completion.
- Close any other input sources you open when you finish using them.
- Hold any admission permit for the HTTP exchange through terminal request completion, including the final transport
  write after the handler returns. See [limit concurrent streams](../../lifecycle/stream-admission/).
- A client disconnect can abort the exchange while output is still pending.
