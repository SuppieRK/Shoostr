## Description

A Shoostr application owns a listener and the resources it has accepted for cleanup. Shutdown first gives active work a chance to finish, then releases owned resources. An application owner must close the application even when it was configured but never started.

This task registers shutdown callbacks and demonstrates caller-managed lifetime. Borrowed application components keep their original owner; registering them for use does not transfer their cleanup automatically.

Register shutdown callbacks while configuring the application, before it starts. Keep the configured instance with an owner that will close it, regardless of whether startup eventually occurs.

| Method        | When it runs                                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `start`       | Called by the owner to compile routes and start the listener. Successful startup freezes registration.                                                     |
| `close`       | Called explicitly, by try-with-resources, or by the JVM shutdown hook. Startup failures after route compilation also invoke it; repeated calls do nothing. |
| `beforeClose` | Registered callbacks run in registration order at the start of the first closure, before native graceful shutdown. Use them to signal long-lived work.     |
| `afterClose`  | Registered callbacks run in reverse registration order after framework and extension cleanup. Use them for final disposal of application-owned resources.  |

Construction registers one JVM shutdown hook, even before startup; explicit closure removes it, while `start()` adds no further hook.
Both shutdown callback lists run synchronously on the closing thread, including when an application closes without starting, and a closed application cannot restart.

Keep signalling callbacks prompt so they do not wait for the handlers they must release.
Caller-owned executor tasks can outlive the native drain, so coordinate those tasks before disposing any resource they still use; see [endpoint executors](../executors/).
Jetty stops its native platform pool with the server, and Shoostr closes the dedicated executor it creates when virtual execution is enabled.
Executors supplied through native configuration remain caller-owned unless their lifecycle is explicitly registered with Jetty.

A rejected route compilation leaves registration open for correction, whereas failures after compilation close acquired resources and prevent another startup attempt.
`RuntimeException` failures from shutdown callbacks are collected without skipping later callbacks or cleanup.
An `Error` stops the remaining callbacks in that phase. Framework cleanup is still attempted,
and the separate `afterClose` phase begins after it; an error in that phase stops
its remaining callbacks. The first `Error` is rethrown after cleanup, with other
failures retained as suppressed exceptions. When no error occurs, ordinary failures
keep the existing `IOException` contract.
