## Description

A response cookie asks a client to store a value and return it on later matching requests. Shoostr's `Cookie` model describes the value, scope and attributes sent in Set-Cookie fields. It is not an HTTP session or a verified identity.

This task sets and updates cookies, then inspects the response fields. `HttpStatusCodes` supplies named numeric statuses; cookie scope and encoding remain explicit application decisions.

Send a `Set-Cookie` field with `response.cookie(...)` and the intended scope. A later request returns matching cookies through the [request accessors](../../request/headers-cookies/). Encode application values for cookie syntax before setting them; Shoostr does not URL-encode or decode cookie data.

Delete a cookie with its original name, path and domain, because the incoming `Cookie` field does not disclose that scope.
Keeping the original `Cookie` value lets `removeCookie(cookie)` preserve both scope and security attributes while sending an empty value, zero `Max-Age` and an expiry in the past.
The [cookie specification](https://www.rfc-editor.org/rfc/rfc6265.html#section-4.1.2) explains scope and expiry in more detail.

## Example

The `/preferences/theme` handlers set, read and delete a harmless theme preference scoped to `/preferences`.
The cookie is host-only and lasts up to an hour; it is not an authentication token or a server-side session.
Use [server-side sessions](../../security/sessions/) for retained session state and [CSRF protection](../../security/csrf/) for cookie-authenticated writes.
Setting another cookie with the same name, domain and path replaces that scope, while cookies with other scopes remain separate.

The secure-preference handlers show `Secure`, `HttpOnly` and `SameSite` metadata for HTTPS use.
Their `__Host-` cookie name requires `Secure`, path `/` and no `Domain` attribute.
Start with `Cookie.secure(...)` before selecting `SameSite.NONE`, since each immutable copy validates its own attributes immediately.
`Max-Age` takes precedence when an explicit `Expires` value is also supplied; neither attribute adds response cache-control headers.
