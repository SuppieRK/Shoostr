## Description

Set a cookie with `response.cookie(cookie)`. Shoostr uses the `Cookie` object's value, scope, and attributes to
send a `Set-Cookie` field. Encode application data to fit cookie syntax before setting the value. Shoostr sends the
value without URL encoding. On later requests, the [request cookie accessors](../../request/headers-cookies/) read
the value without URL decoding.

To delete the cookie, reuse its original name, path, and domain. The incoming `Cookie` header carries names and
values without the original path or domain. Pass the original `Cookie` object to `response.removeCookie(cookie)`
to keep its scope and security attributes while sending an empty value, `Max-Age=0`, and an expiry in the past.

See the [cookie specification](https://www.rfc-editor.org/rfc/rfc6265.html#section-4.1.2) for details on scope and expiry.

## Example

The `/preferences/theme` handlers set, read, and delete a theme preference. The cookie is host-only, applies under
`/preferences`, and lasts up to an hour. Treat the value as a client-supplied preference. Use
[server-side sessions](../../security/sessions/) for session state and [CSRF protection](../../security/csrf/) for
cookie-authenticated writes.

Setting another cookie with the same name, domain, and path in the same response replaces the staged field for that
scope. Other scopes keep their own `Set-Cookie` fields.

The `/secure-preference` handlers show `Secure`, `HttpOnly`, and `SameSite` for use over HTTPS. Shoostr requires
`Secure` and path `/` for a `__Host-` cookie. Leave `Domain` unset.

Create the cookie with `Cookie.secure(...)` before calling `withSameSite(Cookie.SameSite.NONE)`. Shoostr validates
each immutable copy immediately and rejects `SameSite.NONE` unless `Secure` is already set.

When both `Max-Age` and `Expires` are set, clients that support `Max-Age` use it to determine expiry. Set any
response cache policy separately.

## Test

The HTTP tests create the app with `ResponseCookiesExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The client's cookie store returns the theme preference under `/preferences` until the delete response expires it.
The test also checks that setting the preference leaves `Cache-Control` unset. A test-only route replaces and
expires a scoped `theme` cookie while leaving the root `theme` cookie intact. The secure-cookie test checks that the
delete response keeps the original path, `Secure`, `HttpOnly`, and `SameSite`.

The expiry test checks that the header carries an explicit `Expires` date alongside a positive `Max-Age`. The copy
test verifies that the original stays unchanged and invalid attribute combinations throw `IllegalArgumentException`
as soon as a copy is made.

The header checks verify the emitted attributes. Browser enforcement of `Secure`, `HttpOnly`, and `SameSite`
requires browser tests.
