## Description

Use `setHeader(...)` to replace a field's values and `addHeader(...)` to append a separate field. When you read
the values back, each field stays separate and any commas inside it stay part of its value.

Field names are case-insensitive, including in snapshots. Pass a string directly or get the wire name from an
`HttpHeaders` constant with `value()`.

| To | Use |
| --- | --- |
| Replace all current values with one | `setHeader(name, value)` |
| Append a separate field | `addHeader(name, value)` |
| Remove every occurrence | `removeHeader(name)` |
| Read the first value | `header(name)` returns `null` when the field is absent. |
| Read every value in order | `headers(name)` returns an empty list when the field is absent. |
| Snapshot all fields | `headerMap()` |

`headers(name)` and `headerMap()` return immutable snapshots. Later changes to the response leave them intact.

Shoostr manages `Content-Length` and `Transfer-Encoding` as part of HTTP framing. Setting, appending, or removing
either field through the response header API throws `IllegalArgumentException`.

`HttpHeaders` supplies standard names and also supports explicit custom names through `HttpHeaders.of(...)`.

Set headers before the response commits. Access the live `Response` only on its owning thread and during the
request-handling lifetime. See [HTTP field lines](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.2) for how
recipients interpret repeated fields.

`HttpHeaders.of(name)` validates a custom name and preserves its spelling without registering it.
`HttpHeaders.httpHeader(name)` looks up built-in wire names case-insensitively and returns an empty `Optional` for
an unknown name. The lookup includes historical and reserved entries. The reserved `CLOSE` name identifies a
connection option. Keep it out of response fields.

## Test

The HTTP tests create the app with `ResponseHeadersExample.application()`. `TestServer` starts it on an available
loopback port and shuts it down when the fixture closes.

The client receives three separate `Link` fields. The first keeps both comma-separated members in one value.
`X-Mode` changes to `ready` and `X-Temporary` is removed, while the earlier snapshot still holds `draft` and two
`Link` fields.

The snapshot test checks case-insensitive lookup, a missing field, and immutability of both the map and its lists.
The framing test checks that all three mutation methods reject `Content-Length` and `Transfer-Encoding` with
