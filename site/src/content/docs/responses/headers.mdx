## Description

Use `setHeader(name, value)` to replace a field, `addHeader(...)` to append another occurrence, and `removeHeader(name)` to remove all occurrences.
Header names are case-insensitive, so those operations apply to the same field regardless of spelling.

Read the first value with `header(name)`, all values with `headers(name)`, or a complete snapshot with `headerMap()`.
The first-value getter returns null when the field is absent; the collection accessors return immutable snapshots that do not change with later response mutations.
Repeated fields preserve separate values without splitting comma-separated content.

## Example

The `/headers` endpoint captures two `Link` fields in a snapshot before appending another, replacing a mode field and removing a temporary field.
Its body returns both the current values and the unchanged snapshot values.
`HttpHeaders` supplies standard names and also supports explicit custom names through `HttpHeaders.of(...)`.

`HttpHeaders.of(name)` validates a custom field name and preserves its spelling; it does not register the name. `HttpHeaders.httpHeader(name)` looks up built-in wire names case-insensitively and returns an empty Optional for unknown names. Constants also include historical and reserved entries: availability does not make a field suitable for outbound use, and the reserved `CLOSE` field must not be sent.

Set headers before output is committed, and inspect the live response only on its handler thread and within its lifetime.
Shoostr owns framing fields such as `Content-Length` and `Transfer-Encoding`; attempts to set, append or remove them are rejected rather than overriding transport behavior.
For the distinction between repeated fields and their combined interpretation, see [HTTP field lines](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.2).
