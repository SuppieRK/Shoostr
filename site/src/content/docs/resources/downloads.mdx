## Description

Send an application-selected file without loading the whole file into memory. Use `response.file(...)` for
inline output or `response.attachment(...)` to suggest a download filename in `Content-Disposition`.
Both send the file's existing bytes.

- Supply a media type that describes the file, including its charset when applicable.
- Shoostr sends the suggested attachment name in two forms, an ASCII `filename` and a UTF-8 `filename*`.
- Use a nonempty attachment name. Shoostr rejects ASCII control characters and path separators.

Select the path in application code. Validate any request input that influences the path before passing it
to the filesystem. File output works with readable regular files on the default filesystem. Choose one
output mode for the response, since file transfers, finite bodies and streaming are separate modes.
Use [static resources](../static/) to mount a directory.

## Example

The `/file` endpoint sends a CSV report inline. The `/download` endpoint presents the same bytes as
`résumé.csv`. Both endpoints register `HEAD` explicitly so clients can inspect the representation headers alone.

Keep the file readable and its representation stable until the transfer completes. Shoostr stages the
transfer during the handler and sends the file after the handler returns. A handler's `finally` block
runs before that transfer, so wait until transfer completion to delete a temporary file.

A staged transfer can still fail. [Error replacement](../../errors/exceptions/) is possible only before
the response is committed.

## Test

`TestServer` starts the app from `DownloadExample.application(report)` on an available loopback port and
shuts it down when the fixture closes.

The download test saves the HTTP response to a separate file with Java's `BodyHandlers.ofFile(...)`
and checks both filename forms. It verifies the saved copy after the server closes. The other checks
distinguish inline output from an attachment and exercise both explicit `HEAD` routes. They also read the
original report after shutdown, confirming that its storage belongs to the caller.
