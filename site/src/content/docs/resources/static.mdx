## Description

Use `staticFiles(...)` to mount a public filesystem directory, or `classpathResources(...)` for assets already on the application's classpath.
Both mounts serve existing resources through `GET` and `HEAD`; explicit routes take precedence, even when registered after the mount.
Shoostr infers the media type from the filename and uses `application/octet-stream` when the extension is unknown.

Directory listings, welcome files and single-page application (SPA) fallback are disabled by default.
Enable welcome-file or fallback behavior through `StaticOptions` when the mount needs it: a welcome file belongs to the requested directory, while the fallback comes from the mount root.
Fallback does not make unsafe traversal valid, and an external directory alias can select the fallback without exposing its target.

Keep each mount limited to public assets rather than exposing a project or storage root.
Filesystem mounts use Jetty resources and reject aliased paths, including symbolic links beneath the mount. Classpath mounts also reject aliased resources.

Keep the publication directory and its ancestors under the control of the application or deployment owner, with operating-system permissions that exclude untrusted writers. Path checks and file opens are separate operations, so a mount does not protect against hostile concurrent filesystem changes. Replacing the mounted pathname can change later responses or produce a 404; the mount does not retain the original directory after a rename.
Missing resources outside a configured fallback produce `404`.
Keep untrusted executable HTML and JavaScript off the application's trusted origin; follow the [browser trust guidance](../../security/csrf/#description) to use a separate origin and host with host-only application cookies.

## Example

The same filesystem directory is mounted as ordinary files under `/files` and as a SPA under `/app`.
Only the latter enables `index.html` as a welcome file and fallback, while its explicit `/app/version` endpoint still wins over a file with that name.
The classpath directory `/recipe-public` is available separately under `/bundled`.

Mounts use HTTP validators and a `no-cache` policy, which permits storage but requires revalidation; this is not an application cache.
See [file ranges and conditional requests](../caching/) for validator handling, or [downloads](../downloads/) to select a file directly.
Keep source files available through transfer completion, not merely until the handler returns.
