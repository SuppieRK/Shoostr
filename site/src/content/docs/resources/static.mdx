## Description

Serve public files under a single URL prefix. A static mount maps that prefix to a directory on disk or to assets
packaged on the application's classpath.

Mount a public directory with `staticFiles(...)` or packaged assets with `classpathResources(...)`. Both mounts
support `GET` and `HEAD`. A missing resource produces `404` if the mount has no fallback file to serve. Shoostr
chooses the media type from the filename and uses `application/octet-stream` for unknown extensions. Explicit
routes win over mounts even when you register them later.

Directory listings stay disabled. Welcome files and single-page application (SPA) fallback are off by default.
`StaticOptions` enables either behavior.

- A welcome file comes from the requested directory.
- An SPA fallback comes from the mount root. Shoostr checks it when a request has no file or welcome file to serve.

Shoostr rejects unsafe traversal even with fallback enabled. When a mount rejects an external directory alias,
it can still serve its SPA fallback from the mount root.

- Mount only public assets. Keep project and storage roots outside the mount.
- Filesystem mounts use Jetty resources and reject aliased paths, including symbolic links beneath the mount.
  Classpath mounts also reject aliased resources.
- Keep the mounted directory and its ancestors under the control of the application or deployment owner.
  Use operating-system permissions to exclude untrusted writers. A writer could otherwise change the
  filesystem between Shoostr checking the path and opening the file.
- Later requests still use the mounted pathname after a rename. Replacing or moving the directory can change
  later responses or produce `404`.
- Serve untrusted executable HTML and JavaScript from a separate origin on a separate host. Keep application cookies
  host-only. See the [browser trust guidance](../../security/csrf/#description).

## Example

| Prefix     | Source                               | Behavior                                                                                                                             |
| ---------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `/files`   | Filesystem directory                 | Serves ordinary files.                                                                                                               |
| `/app`     | Same filesystem directory            | Uses `index.html` for welcome files and SPA fallback. The explicit `/app/version` route takes precedence over a file with that name. |
| `/bundled` | Classpath directory `/recipe-public` | Serves packaged assets.                                                                                                              |

Mounts use HTTP validators and `Cache-Control: no-cache`. HTTP caches can store the response and must revalidate
it before reuse. See [file ranges and conditional requests](../caching/) for validator handling or
[downloads](../downloads/) to select a file directly.

Keep source files available until the transfer completes.

## Test

`TestServer` starts the app from `StaticResourcesExample.application(...)` on an available loopback port and
shuts it down when the fixture closes.

The tests create both resource directories and make the bundled files visible through a temporary classloader.
They check media types, `HEAD` metadata, welcome files, fallback and explicit-route precedence. The path checks
cover a missing file, rejected traversal and an external directory alias that selects the SPA shell under
`/app`. The alias test uses a directory junction on Windows and a symbolic link on other systems.
